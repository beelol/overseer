## Panel and controls

`m` is added only to Grid/Zoom navigation; dashboard Grid falls through its existing navigation handler. It never captures Compose/NewAgent/Overseer input. Preserve uppercase M/P and Audio/Changes p. With a focused run, open Applied; without one, open Library. Tab/BackTab switches Applied/Library; Esc closes to the saved original mode. Panel-local `r` refreshes and `?` toggles local help without switching to the generic Help mode.

Applied shows the explicit target, daemon context, desired decisions/reasons, pending, and last recorded outcome/digest/bytes, plus support/notice. A prepared, failed or uncertain snapshot is not delivered; absent snapshot says “No recorded turn delivery.” Library contains installed pinned versions, bindings, bundled availability and unavailable entries. Less tool noise stays visibly planned/inactive, with no savings claim. Lists/details scroll so narrow terminals retain reachable controls and readable labels.

Inside Mods only, `a` picks an ordinary run from the daemon roster and `O` selects the actual current Overseer run from `state.overseer.run_id`. The state summary comes from a nonmutating SQL read; `overseer.session` can create an idle session on first use, so this view need not call it. Missing Overseer run is a useful empty state, not a fallback to another agent. Refresh state on explicit Overseer selection, guard its request purpose, and then read why for the returned exact run id. Fresh/session changes invalidate the old target result and confirmation. An Overseer-scoped library binding needs no active run.

Library local actions: `i` opens an install source form (bundled Clear prose or local folder); `u` opens an update source form for the selected installed version; Enter reviews an immutable preview; `b` creates a scoped binding for the selected version; `e` edits the selected binding; `d` removes the selected installed version; `x` removes a selected binding override. Installed versions and bindings are distinct selectable rows. Binding form visibly edits enabled/disabled, required and locked, and all five scopes. Repository/agent target fields come from daemon context/roster choices; never substitute a worktree path for repo_key. Preserve exact filters on edit. Filter lists use individual exact-ID entries with add/remove controls, rather than splitting identifiers on commas or rewriting route meanings. New bindings default to unfiltered, optional and unlocked. All-agents and Overseer are explicitly separate labels.

Preview renders source, operation, version, fingerprint, files/contents, permissions/unsupported and redaction notice. Both install and update commit through `mods.install({preview_id,confirm:true})`; operation belongs to the preview. There is no mods.update RPC. Installation never calls bind. A changed source form must request a fresh preview; a confirmation refers to the existing immutable preview only.

## Authority, revisions and lifecycle

This is the local owner client over its existing socket; do not invent a client role, auth token, native flag or scope resolver. Use daemon-generated version fingerprints, binding ids, repo keys and returned desired/support/outcome facts. Every bind/unbind/remove sends the reviewed exact expected_revision; bind pins mod id/version/fingerprint. Editing preserves binding id and all untouched scope/filter/required/locked fields. Explicit disabled override differs from unbind, which may reveal inherited enablement. Owner lock changes are explicit form changes, never a silent conflict repair.

The list revision and desired plan revision must agree before preparing a mutation using both views. Mismatched snapshots display pending refresh and block writes until coherent fresh facts arrive. They must never be combined into a binding just because each individual read succeeded.

Install/update/removal, scoped binding changes and unbind each get a dedicated review prompt. Only y/Y confirms; n/N/Esc cancels; unrelated keys leave the question visible. A request is sent once and repeat input is blocked while pending. On revision conflict display the daemon error, refresh facts and ask for a new review; never replay the mutation automatically. Confirmation requires the same connection generation and current reviewed revision/preview/target identity.

Disconnect invalidates pending reads, previews and confirmations, marks retained facts stale and disables writes. Reconnect refreshes list/current-target why. Every Mods pending purpose carries connection generation, panel/read epoch and exact target where relevant; a reply for an old target or closed panel cannot populate the current view. Coalesce global mods_changed and the current envelope run_id's mods_applied through one panel-only scheduled refresh using existing tick, with an inflight/dirty flag. Do not inspect event payload text or use payload run_id to choose a target, create polling or copy public event text into forms. Relevant session/state changes refresh the explicit Overseer target; late session reads cannot replace an ordinary target selected meanwhile.

## Execution rulings

- Refresh cancels binding/filter drafts and outstanding review prompts. RED proved that retaining old fields while adopting a new revision could overwrite a concurrent owner edit. This deliberately loses an unsaved draft, with an explicit notice, rather than silently rebasing it.
- A sent operation retains its original epoch/target until acknowledgement; an intervening session change immediately marks retained facts stale and switches/refetches after that acknowledgement. The operation is never replayed.
- Public titles/harness/transport/outcome labels are presentation only; raw selector identity and immutable request bytes are preserved.
