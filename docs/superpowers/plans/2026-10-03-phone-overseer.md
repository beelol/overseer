## Review Focus

1. Authenticated phone identity must survive typed bare yes/no as well as button approval; client `surface`/`by` must not spoof voice, VS Code or another device. Task 1 tests both paths.
2. Concurrent phone/Mac answers and reconnect resends must produce one winner/action; a revoked or downgraded device must not execute a pending answer. Task 1 tests gateway arbitration and scope changes; Task 4 tests the screen's losing answer.
3. A disconnect longer than one message page, event replay overlapping a snapshot, and messages arriving during loading must lose or duplicate nothing. Task 2/3 tests distinct message/event cursors and bounded backward paging.
4. A shared session replaced by Start fresh, or pairing forgotten/revoked during an in-flight request, must not resurrect the old conversation or cached proposals. Task 3 tests generation invalidation and cache deletion.
5. Overseer's run is hidden; proposals and conflicts still produce exactly one visible, navigable Needs item, even on a watch phone. Task 4 tests count, identity, row and navigation rather than adding a badge alone.

## Task 2: Lossless message paging with existing-client compatibility

**Files:** `daemon/src/overseer/session.rs`, server dispatch, protocol types; tests in phone_methods.rs and existing overseer.rs.

**Interfaces:** Keep `overseer_messages(after, limit)` and its tail-first defaults for existing Rust callers. Add an internal `overseer_messages_page(after: i64, before: Option<i64>, limit: i64, session_id: Option<&str>) -> Result<Value>` used by dispatch. Return `{session_id: string, messages: OverseerMessage[], has_more: boolean}`. Bounds are exclusive `seq > after` and `seq < before`, newest eligible page sorted ascending in the reply, limit clamped 1–500 as today; `has_more` means older eligible rows remain. A supplied non-current session id fails `stale_session`; it cannot silently page another session.

- [ ] Write `ac128_message_pages_have_no_gap`: seed more than 500 real session messages (use existing fixture/SQL test helpers), page backward from the latest reply's oldest seq, merge by message id/seq, and assert all messages exactly once in ascending order. Distinguish `overseer_messages.seq` from daemon event seq and session `last_seq` (neither is a valid substitute). Include other sessions so message seq need not be contiguous.
- [ ] Write compatibility assertions: default 50-message session snapshot and existing messages tail defaults remain unchanged; `after` + `before` bounds, malformed bounds, session replacement and empty pages behave explicitly.
