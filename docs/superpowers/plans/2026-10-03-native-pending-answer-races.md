## Independent expected native output

The seven-family matrix compares complete native replies to committed fixtures/transcripts/ac274/native-vectors.json response objects: file_decline, permissions_empty_deny, codex_question_id, codex_form_accept, claude_deny, claude_question_text and claude_form_accept. Their only submitted question change is replacing the native answer selector with public field-0; expected output stays the frozen native identity/content. No expectation calls the runtime codec. Concurrent decline/cancel now uses both frozen response objects. Child/tagged-ID variations change only the expected raw response ID explicitly, preserving the frozen response body. Secret-answer variation changes only the expected answer content to a synthetic opaque value.

Negative helper now examines actual socket error.code, not any error string. Contract categories proposed for runtime are invalid_answer (wrong family), stale_request (revision), invalid_params (caller authority/unknown fields), scope_enlarged (profile deny deletion/glob widening), native_veto (suppression), request_resolved and stale_generation. Wrong-family/revision/extra-authority and profile negatives end with a valid same-request frozen response control. Native veto already has a valid allow-once control; old-generation refusal is paired with the replacement's valid response. A resolved native item has no valid same-item answer; its terminal native_resolved projection and zero pending_count are independently asserted before submission. Terminal current-generation projections are retained, not assumed absent.

Direct shim token conflict now submits changed bytes with a new valid SHA256 digest, distinguishing receipt_conflict from malformed digest. Wrong generation expects stale_generation. The first successful actual write and subsequent status query remain controls. This is a proposed typed private operation, not native provider capability.

## Proposed deterministic hook contract

Only explicit synthetic fixture processes may enable a proposed gate, through daemon/shim startup environment (not method parameters), requiring the incumbent explicit test-net guard plus FIXTURE_MODE=native-pending. Gates live under an existing test-owned private directory, with phase and opaque request key/token selectors. Reached marker contains only selector/phase; no answer, raw ID, descriptor or actor-supplied authority. Every wait is bounded30s, cancellable, and releases Store and authorization/process locks. Timeout must return a static definitely-unsent refusal if no write was attempted, or uncertain if an effect may have begun, never implicitly approve/send. There is no sleep-based race assertion.

Proposed daemon phases: validated_before_claim and claimed_before_send. Claim phase still commits the immutable attempt token/digest/provenance under its normal locks. A held worker must not hold the process gate, so the actual tail can apply resolution and the real owner can advance process generation. Reacquire the process gate, reload exact item/claim/revision/generation and fresh trusted device state before the first control write; this is the required second validation, not rebinding to a replacement. Claimed token wins arbitration while locks are released; a rival cannot generate another send. No lifecycle/public event is fabricated by the fixture.

Device scope/revocation needs an explicit final authority ordering choice before runtime: checking under Store at claim alone does not protect a held accepted attempt. Prefer a per-device authorization gate outside the process gate for the final bounded send, and have device_scope/device_revoke take that gate before Store. Order is device authorization gate → process gate → Store; the gate is released for fixture presend waiting, then all authority is rechecked. An acknowledged revocation/scope change before the final send wins; revocation arriving during an already-started bounded write waits for that disposition, without pretending to undo bytes. No Store lock is held during I/O. Existing local owner/voice routes do not infer device authority from display actor. This requires root source/design review, not assumed implementation.

The new typed pipe write must be bounded; current legacy stdin uses blocking write_all. Proposed request_reply uses a deadline and temporarily nonblocking writes under the existing stdin mutex, restoring flags before legacy operations. Durable prepared receipt precedes the first actual pipe write; complete write/flush produces written, partial/deadline failure remains uncertain, and a pre-touch refusal produces not_written. This new private boundary must not make legacy stdin or arbitrary native data public.
