> **For agentic workers:** Use superpowers:executing-plans task by task in the prepared implementation worktree. **Goal:** Let the owner install, scope, inspect, disable, and remove the optional Clear prose mod, with exact per-turn delivery records and separate bindings for agents and Overseer.

**Architecture:** The Rust daemon owns immutable mod versions and persistent bindings; a deterministic resolver prepares each turn's text and records how it reached the harness. Mods remain ordinary manifest/text bundles, delivered from run-owned files or explicitly labelled message text. Client surfaces call the same daemon methods; Phase 1 executes no mod program.

**Tech Stack:** Existing Rust/SQLite/serde/sha2 daemon, one TOML parser dependency, existing JavaScript VS Code webviews, Rust TUI, TypeScript phone protocol and views.

**Spec:** `docs/rfcs/mods-first-release.md`, `docs/rfcs/mods.md` (owner answers and chosen approach), `docs/design/mods/clear-prose-rules.md`, `docs/design/mods/evaluation.md`.

## Global constraints

- Both requested bundles are optional and off by default. Phase 1 implements Clear prose only; Less tool noise remains explicitly unavailable.
- All-agents bindings exclude Overseer's session. Session bindings apply on its first and subsequent turns through the same resolver.
- No mod code in the daemon, no transformer, dependency installer, paid compression call, automatic install, or repository recommendation file in this phase.
- Owner configuration, auth, credentials, repo instructions, approvals, sandbox, role tools, guardrails, model, and effort are not changed by mod text. No arbitrary mod `extra_args` or environment entries.
- Installing, updating, and removing are product-level confirmed actions. Owner-authorized development proceeds without further planning approval.
- Only `gpt-5.6-luna` at low effort for future paid checks; no paid Claude turn; one attempt per step, no retries. Instruction fixtures prove delivery, not prose quality.
- Criteria/ledger go on main through the coordinator. Implementation is committed/pushed criterion by criterion on its own branch/PR. Full suite required before readiness; no merge while builder is working.
- Future builds/tests use `nice -n 20`; respect `scripts/test-all`'s machine lock and one UI scenario at a time outside full runs. No UI while a full run holds the lock; leave no processes/windows.
- Use existing Overseer mark and design tokens. No remote icons, new mark, or hard-coded colours needed for the first text bundle.

## Releasable slices

**1A — Useful daemon and CLI:** install bundled/local text mods, set/clear bindings, inspect proposed versus last delivered set, deliver Clear prose to eligible agent and Overseer turns, and remove it. `overseerd ctl` is sufficient CLI; a new command parser is unnecessary. Unknown native capabilities use a labelled text fallback only when policy permits; otherwise show unsupported. Required unsupported pieces refuse before spawning.

**1B — VS Code:** a Mods management panel and Applied view, with install preview, scope controls, status, story, and keyboard operation. It releases independently of phone/TUI.

**1C — Other surfaces and conversation:** TUI management, phone read-only inspection, and Gate S Look/Steer/Confirm integration. Group support starts with watchers; Swarm category and Overseer-started provenance need dedicated integration rather than inferred prompt text and may follow this slice.

The full Phase 1 spec spans several subsystems. Do not label 1A as complete Phase 1. Native/global configuration qualification and live prose quality remain explicit gaps until their tests pass; they do not prevent shipping an accurately scoped local-library/CLI release.

## Review focus

1. A second install changes the same named version's bytes: require a new preview/fingerprint and leave current bindings pinned. Task 1 tests it.
2. A binding changes between turn creation and process spawn: the persisted turn plan wins; an in-flight turn never changes. Task 3 tests it.
3. The first Overseer turn resolves before the session's later bookkeeping: use `run_roles`, written by `create_task` before launch, not visibility or title. Tasks 2/3 test it.
4. Existing global instructions/skills or project security rules are present: suppression must target global text only and preserve project policy/auth. Unproved suppression is visible and cannot satisfy a required isolated mod. Task 3 tests it.
5. A client disconnects during a confirmed install/removal: retrying the same preview is idempotent and reconnect reads daemon truth. Tasks 1/4 test it.

## Contracts for Slice 1A

Create `daemon/src/mods/{mod.rs,manifest.rs,library.rs,bindings.rs,delivery.rs}` and `mods/clear-prose/{mod.toml,style.md}`. Register `mod mods;` in `daemon/src/main.rs`. Embed bundled manifest/text bytes with `include_bytes!` so packaged daemon installation does not depend on its source checkout. `style.md` exactly matches the saved rules source; a test prevents drift.

Manifest schema 1: `schema_version`, `id`, `name`, `version`, `summary`, `source`, optional `homepage`; `[rules] files = [...]`; optional `[style] file = "style.md"`. Recognize tool/hook/program/limit/harness-option descriptors for display but never run them. Unsupported pieces are listed with reasons; code-containing imports cannot be committed as active text-only mods. Reject unknown schema versions and unknown permission/launch keys rather than ignoring them. Initial ids are lower-case letters/digits/hyphens, 1–64 bytes; versions are nonempty, 1–32 bytes. Manifest limit 64 KiB, text file limit 32 KiB, total bundle limit 1 MiB/128 files, aggregate delivered mod text limit 16 KiB. Reject absolute/parent paths, symlinks, special files, invalid UTF-8 text, and path escapes; source is copied once into an immutable staged tree before hashing/preview. No shell is used to import files.

Shared types:

- `ModVersion { id, version, fingerprint, manifest, files, source, installed_ms }`; fingerprint is SHA-256 of sorted relative-path/length/content records, including manifest.
- `ModScope`: `AllAgents`, `Repository { repo_key }`, `Watchers`, `Agent { run_id }`, `Overseer`. Unknown group ids return `unsupported_scope`; do not silently broaden them.
- `ModFilters { harnesses: Vec<String>, accounts: Vec<String>, models: Vec<String> }`; empty means unfiltered, exact ids only.
- `ModBinding { id, mod_id, version, fingerprint, scope, enabled, required, locked, filters, changed_ms, actor }`.
- `ModBindingInput { id: Option<String>, mod_id, version, fingerprint, scope, enabled, required, locked, filters }` is the mutation input; timestamp/actor are assigned by the daemon. Reject caller-supplied actor/role/time fields. Only a direct owner request may change `locked`.
- `ModContext { run_id, role, repo_key, harness, harness_version, account_id, model, native_thread_exists }` from daemon state, never caller-supplied role/permissions.
- `ModPlan { revision, versions, rules_text, style_text, decisions }`; `ModDecision` carries binding reason/overrides, delivery (`native_instructions`, `message_text`, `unsupported`), activation (`next_turn`, `next_thread`), children (`yes`, `no`, `unknown`), byte size and estimated-token method if shown.
- `AppliedMods { desired: ModPlan, last_turn: Option<TurnModSnapshot>, pending: bool }`. A snapshot has turn id, fingerprint/version/binding ids, delivered digest/text-byte size, delivery decisions and launch outcome; never claim launch success merely because the plan was resolved.

Add additive tables in `Store::migrate_main`: `mod_versions`, `mod_bindings`, `mod_previews`, `turn_mods`; a monotonic Mods revision in existing `meta`. Do not put Mods in the learning/account-booking DB. Store text and file list with the version so resolution takes no filesystem I/O under the store lock. Stage/rename files outside that lock; SQLite transaction commits version, revision, and story event together. Mutation requests compare their expected revision; conflicts return current state instead of overwriting concurrent changes. Interrupted stages remain private and are cleaned on daemon startup. Text snapshots are copied into turn storage, so removal of installed text does not break an active turn or historical snapshot.

Public daemon methods, explicit dispatch arms in `server.rs` and matching `protocol/protocol.json` shapes:

- `mods.list {}` → `{ revision, installed, available_bundled }` (`read`). A bundled option is available, not implicitly installed/enabled.
- `mods.preview { source: "bundled:clear-prose" | absolute_folder, operation: "install"|"update" }` → immutable preview id/fingerprint/file list/diff/permissions/unsupported reasons (`mac_only`). Preview is staged source, not a later re-read of mutable source.
- `mods.install { preview_id, confirm: true }` → installed version/revision (`mac_only`); reject absent confirmation and repeat idempotently.
- `mods.bind { binding: ModBindingInput, expected_revision }` → current binding/revision (`mac_only`); installed text only. Owner unlock is an explicit mutation; no agent/Gate S may unlock.
- `mods.unbind { binding_id, expected_revision }` → revision (`mac_only`); removing an off override reveals broader on.
- `mods.why { run_id }` → `AppliedMods` (`read`); use the actual hidden Overseer run id too, never manufacture it.
- `mods.remove { mod_id, fingerprint, confirm: true, expected_revision }` → ended bindings/revision (`mac_only`). Refuse unconfirmed, list affected bindings, remove only this version's installed files, keep recorded turn history.

The existing CLI is immediately usable, for example `overseerd ctl mods.list '{}'`, preview followed by confirmed install, then bind. Document JSON scope examples in `docs/rfcs/mods-first-release.md` after implementation; no paid agent is necessary to manage a mod.
