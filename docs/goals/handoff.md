## Pitfalls learned (so they don't repeat)

- **`CARGO_TARGET_DIR` must be absolute.** A relative one breaks the TUI tests, which run from another folder.
- **Never `git add -A` in a throwaway merge.** Stray `node_modules` symlinks get committed. `.gitignore` now says `node_modules`, without the slash, to catch links too.
- **Two runs must never share a log file.** A second run truncates the first run's log.
- **In zsh, `kill $pids` doesn't split the list.** Use `xargs`.
- **A test-all blocked in a child ignores SIGTERM until that child ends.** Stop its children first.
- **Merge markers can name a branch, not a SHA** (`>>>>>>> gh/main`). Match `>>>>>>> [^\n]+`.
- **Never renice by a broad pattern.** It caught the owner's installed daemon once. Exclude `~/.vscode/extensions/`.
- **Public status pages are off in tests** (`OVERSEER_PUBLIC_STATUS=off`). A real Claude outage once failed three Auto tests on main.
- **notify-agents and popout check that test windows never take the focus from the owner's apps**: they fail whenever the owner is at the Mac (on main too). Run them, and AC-149's three clean full runs, when the Mac is idle (`ioreg -c IOHIDSystem` HIDIdleTime over 10 minutes).
- **Never share a `CARGO_TARGET_DIR` between a builder's worktree and the coordinator's merge copy.** On 2026-10-02 #49's copy reused test programs the builder had compiled in its own (since deleted) worktree: a scratch test that isn't in the code appeared and 29 tests failed on paths into the deleted folder. Give each merge copy its own target folder.
- **In every merge copy, regenerate the generated files before testing:** `python3 protocol/capabilities.py && node protocol/gen-ts.mjs`, and commit them to the branch if they change. Twice (#43, #49) the README's phone table was stale after a merge and failed the gateway's class test.
- **A full run takes about 2 hours now** (Rust ~30 min, 80+ UI scenarios one at a time). A background command is stopped at 2 hours: split the run (`--no-ui`, then the UI scenarios) or give it the most time allowed.
- **Builders must block, not just warn, before a UI scenario.** Twice (#47's and #50's builders) a builder's check printed the lock / quiet-window state and started a scenario anyway during the coordinator's run. Give them this exact wait: `until [ ! -e $TMPDIR/overseer-test-all.lock ] && [ ! -e $TMPDIR/overseer-quiet-window ] && ! pgrep -f '^node test/ui/scenario-' >/dev/null; do sleep 30; done`.
- **A loop over UI scenarios must skip the LIVE ones, as test-all does** (first line of the file contains `LIVE`). On 2026-09-30 the coordinator's hand-written loops for #38 and main ran background (a Claude Haiku turn, twice: against the owner's no-Claude rule), codex-approval, codex-follow, merge and offline-session (gpt-5.6-luna; two without an explicit low effort). The owner was told. Filter: `head -1 test/ui/scenario-$n.js | grep -q LIVE && continue`.
- **Never `git commit -a` in a worktree after a full run there.** The run rewrites hundreds of evidence files; commit only the files you changed.
- **`/private/tmp` is wiped on reboot.** Push work, and keep notes on main (this file) or in memory, not only in the scratchpad.
