## Existing contract to reuse

`protocol/protocol.json:2951–3038` already defines both reads and all five local management methods. `mods.list` returns `revision`, `installed: json[]`, `bindings: ModBinding[]`, `available_bundled: json[]`, `unavailable: json[]`, and `support: json`. Installed/available entries contain id, version, fingerprint, manifest, source, installed_ms, and file metadata (path, original byte count, SHA256), not file bodies. In `daemon/src/mods/library.rs:341–355`, Clear prose is available and Less tool noise is explicitly planned with external transformers unimplemented. Render that reason; no activation control or savings estimate for Less tool noise.

`mods.why({run_id})` returns `AppliedMods`: context, desired plan, nullable last_turn, daemon-computed pending, support, notice. The desired plan contains revision, pinned versions, rules_text, style_text, and binding decisions. Decision status includes unqualified as well as selected/disabled/overridden/filtered/not_in_scope. There is no per-decision token estimate. Context includes daemon-owned `local_model_selection`; clients must not recompute applicability from a role string or infer current selected local model support.

The last snapshot contains immutable original digest/added_bytes, planned/applied fingerprints, outcome, outcome detail, and `text_redacted`. Show desired separately from the last recorded turn. Prepared, failed-before-effect, and uncertain-after-effect are not successful delivery. A missing snapshot must say no recorded turn delivery even when pending is false. Public redaction can change displayed text while the digest and byte count still identify private original bytes.

Support currently says message-text implementation, installed runtime/native configuration unverified, global suppression and dynamic-local delivery unsupported, child inheritance unknown. Keep those qualifications visible. Installing never enables; turning off cannot erase earlier instructions from session history. Text guidance changes no permissions or repository rules.

Management methods are `mods.preview` (operation install or update), `mods.install` (immutable preview_id plus confirm), `mods.bind`, `mods.unbind`, and `mods.remove`. There is **no mods.update RPC**: update is preview then confirmed install. Bind/unbind/remove carry exact expected_revision. Remove also carries exact mod id/fingerprint and confirmation. Never automatically replay a stale mutation after refresh; show the changed revision and let the owner review again.

The generated phone types already expose reads and exclude these five mac_only methods. Task 5's proposed protocol/generated-file edits are unnecessary unless an actual contract change is justified. Classification is derived from the protocol in `daemon/src/gateway/classes.rs:65–112`; there is no second handwritten gateway Mods allowlist to maintain.

## TUI slice

Create `tui/src/app/mods.rs` and `tui/tests/mods.rs`; integrate only necessary mode, pending, confirmation, event and UI/help handling in `tui/src/app.rs` and `tui/src/ui.rs`. Reuse the Requests boundary and request-id dispatch used by the existing Audio/phone screens. Store the panel state separately from the mode: target, library/applied tab, selected pinned entry, scope draft, loading/error, preview, exact revision and return mode. Keep typed owner-edit forms bounded. Supported scopes are all_agents, repository, watchers, agent and overseer; use daemon binding ids and repository identity, not guessed paths or a locally resolved role. Expose existing filter/required/lock values as binding edits, without implementing another precedence resolver.

Lowercase m is free in Grid/Zoom (`app.rs:2874` onward). Open Applied for the focused run, Library when no run exists; Tab/BackTab switches library/applied. Preserve the exact originating Zoom scroll or dashboard state on Escape. Uppercase M/P keep merge/PR actions. Lowercase p remains Audio preview (`app.rs:2496`) and previous change (`app.rs:2598`). Compose and form text, including the letter m, must remain text.

Use local panel actions for preview/install/update, scoped enable/disable, removal, override removal and refresh. Installation/update must show the staged files/source/version/fingerprint and require explicit yes; binding changes are a separate action. Show an explicit disabled override separately from removing an override (which can reveal an inherited enabled binding). Display lock conflicts and unsupported filters from the daemon without silent unlock or scope substitution.

A stale assumption is the generic Confirm handler (`app.rs:2747` onward): it resets to Grid even on arbitrary keys. Add a Mods-specific confirmation path that accepts only y/Y, n/N/Esc and restores the panel, following the dedicated phone confirmation pattern (`app/phone.rs:529`). Do not refactor unrelated confirmations. Preserve the panel behind the prompt rather than falling through the default Grid renderer.

Another gap is the own-session target: TUI state requests do not request include_hidden, so the current Overseer run is not reliably in State.runs. Use the daemon's state.overseer/session run_id for an explicit Overseer Applied target choice; do not select the most recent ordinary agent. A library binding scoped to Overseer needs no active session. Do not add m to the Overseer composer, where it would consume typed text.

On disconnect clear pending requests, invalidate preview/confirmation, mark retained read data stale and disable writes. On reconnect refresh list and current target why. Use connection generation and target/request identity so a late reply cannot replace another run's Applied view. Refresh on mods_changed and the current target's mods_applied; the daemon remains the status authority.

## Phone slice

Create `phone/src/screens/ModsScreen.tsx`, its screen tests and `phone/app/agent/[run]/mods.tsx` re-export. Add `routes.mods(run)` using encodeURIComponent and a Mods item in HeaderActions. Reuse Screen/Txt/Empty, theme tokens and existing navigation/accessibility patterns. Normalize the Expo run parameter, including arrays/missing values; missing run must not issue mods.why with an empty id. This is an inspection screen: no preview/install/toggle/unbind/remove, unlock request, or queued control.

HeaderActions currently builds More items only for selected action states and renders More only when there are items (`HeaderActions.tsx:88–118`). Put Mods outside the idle/worktree/!watch mutation branches so watch, working and child agents can reach it. Do not make inspection depend on a live worktree. Expo Stack discovers file routes; no manual root Stack registration is needed.

Use useSession.request for list/why, and useSessionValue for online/scope/stale-state display. Guard asynchronous responses by run/generation and screen lifetime; partial list/why failure needs separate useful errors. Keep an explicit refresh control and show last-confirmed information as stale offline, never successful current delivery from cached data. Session exposes getSnapshot/subscribe/request, not a public raw event hook (`phone/src/session/session.ts:139–145,202–204`). Conversation review's useActivity does not reliably observe global mods_changed with no run target. Snapshot stateAt/lastContact can trigger bounded refresh but are timestamps, not a guaranteed Mods revision signal: same-time unrelated/global batches can be indistinguishable. Therefore the bounded first implementation should guarantee refresh on entry/reconnect/manual refresh, and label that behavior honestly; if automatic every-event freshness is required, add a small explicit public Mods revision/event signal with tests in a separately identified Session change rather than accessing private connection dependencies or inventing polling. The approved Task 5 does not currently require that new signal.
