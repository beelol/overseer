## Twelve meaningful trigger contracts

For every line below: off, replayed pre-start events, stale process/request/revision, duplicate transition, child/worker, watcher/shared Overseer internal work, and stale queued playback are negative controls. These must be exercised at the actual daemon-to-synthetic-audio-sink boundary, not only by feeding classify() its expected string. Installed/by-ear pack quality remains owner evidence.

## Cross-cutting source findings and focused fixture candidates

1. **Exactly twelve canonical keys are not implemented.** audio.rs15 KEYS contains legacy reserved progress/queued/resumed/stopped/unblocked/review/delivery/verification keys; DEFAULT_KEYS only three; system phrases564 only three. The prior standard reused Reactor assets; the new standard instead requires a complete pack whose spoken content matches each canonical line. Test all12 key/phrase mappings plus refusal of old noncanonical event keys; assert every trigger family above reaches its key across Built-in/From folder rather than only preview key inventory. Existing test count==12 is insufficient: it counts the wrong12.
2. **Worker/director suppression is incomplete.** audio.rs444 filters only run_role overseer/watcher and parent_run_id. daemon.rs1175 creates managed Swarm processes as top-level; role assignment1255 accepts only overseer/watcher. Authoritative memberships already exist in swarm_worker_launches/swarm_director_owners and daemon state3943. Fixture: director start/complete + workers start/permission/fail/complete, objective open: zero constituent cues; actual Swarm-ready/complete/stalled transition exactly one proper Swarm cue. Proposal/conflict branch executes BEFORE run-role/root filter, so test child/worker-associated owner events too.
3. **Recovery gates need semantic outcomes.** classify ignores attention/error/retry/handoff/availability and cannot distinguish terminal failure from an exhausted-but-resumable need. Source does correctly park connection/memory before final status via handoff::park; retain this. Fixture all retry successes silent, final exhaustion emits exactly right blocked/sign-in/stopped/failure line, queued earlier candidate cancelled if recovery succeeds before playback. Do not turn every stalled/failed/database state into exhausted policy by assumption.
4. **Need identity and repeated transitions are too broad.** attention HashSet is run_id only, cleared by running/starting/queued/interrupted/completed status. Typed answer refresh_attention clears/updates status in Store but emits pending_request_changed, not a matching running event; current Audio never consumes that change. Two sequential native needs on one run can remain muted, while interrupted/queued can clear an unresolved need and let duplicates sound again. Fixture permission→actual answered/resolved→new question, multiple queued pending on same run and rev/native generation rollover; track exact opaque key+revision/state transition, never transport ack as resolution.
5. **Coalescing drops instead of aggregates.**800ms BurstGate keeps one generic key and a1024-run arbitrary-eviction set; repeated proposal open has only temporal gate, no durable proposal identity. Fixture two different-needs same moment (and start/completion interleaved), duplicate status/permission for one need, two proposals separated>800ms stillsameopen, unresolved>1024 bookkeeping bound. Require one aggregate for >=2 eligible distinct agents, silence for stale/settled arrivals and preserve all UI needs.
6. **Queued playback lacks freshness.** Cue holds only key/preview/Selection, no owner/key/generation/source transition. After queue wait or Voice wait (floor.rs256 up to5/10s), play never rechecks need resolved/current generation/pack switch/enabled flag. Off is checked only immediately after dequeue. Fixture hold arbiter, resolve/revoke/replace/disable/switchpack while queued, release: old/stale automatic cue silent; valid current cue exactly once. Keep explicit previews separate and retain bounded queue4/urgent2/singleplayer. Player .status() has no deadline; missing/corrupt/slow player must not make the queue permanently stale or block shutdown.
7. **Voice supplements violate new silent-action vocabulary.** voice/request.rs507 heard signal uses agent_queued;1430 owner allow/deny cues agent_unblocked/agent_stopped. New owner instruction says exactly12 and owner actions deliberately silent. Preserve the separate Voice heard/confirmation semantics only via an explicitly approved non-spoken channel, not extra Audio spoken lines. floor.rs260 recognizes urgency only for legacy agent_needs_attention; new attention/Swarm keys would be dropped as routine while owner speaks unless classification is updated. Fixture arbiter tests every applicable urgent line + no action cue, no self-capture.
8. **Pack/API/UI is still three track types.** Track parse reactor/system/commander; Commander validates only three hard-coded WAV locations142; extension1087–1127 offers Reactor/System/Private Commander and reactor manifest previews. No audio-pack.json schema/path validation or Built-in/From folder switch. Candidate fixture packs must be freshly synthetic, never copy/read POD. Require all twelve canonical keys and no silent fallback under the latest contract; unknown keys, traversal, absolute/symlink escape, malformed dictionary/unsupported media, missing/remove/replace folder, simultaneous toggle/selection, daemon restart, and no private file/cache/upload path. Current code plays Commander in place (good invariant); built-in cache is separate. Avoid merely renaming UI while leaving incompatible settings/protocol/native clients.
