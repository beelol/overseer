## Official public status as advisory health (2026-09-26)

- [OpenAI's official summary feed](https://status.openai.com/api/v2/summary.json) currently names separate `CLI` and `Codex API` components; [Claude's official summary feed](https://status.claude.com/api/v2/summary.json) names `Claude Code`. A read-only local fetch observed those exact component names as operational on this date. Auto now reads only these fixed HTTPS URLs with a credential-free bounded process, a 128 KiB response cap, and at most 750 ms of the decision deadline. Missing, duplicated, or changed relevant components produce unknown rather than a global outage claim. Feed content is reduced to component scope/status; incident prose and arbitrary response fields are not retained.
- A public incident only degrades the matching endpoint's ranking; it cannot hard-block a working route, clear an account's exhausted allowance, or stand in for a direct 429/503/authentication signal. A recent successful route beats a later page refresh because fetch time is not incident start time. The selector prefers an independent unknown route over one degraded by a matching advisory incident, while direct account/endpoint failures retain their stronger scope. Controlled parser/selector tests were written red before the change. Actual public status is not proof of task capability or account availability; AUTO-AC-09 and 10 remain open for host connectivity, cache age, recovery, and broader source drift.
- The changed health order is recorded as selector `multi-harness-preflight-v2`; replay of older decisions uses their earlier health ordering. A fixture demonstrates that the same degraded/unknown inputs choose different routes under the old and new versions without rewriting stored history. This feed is an optional read-only signal: unavailable curl, network denial, or schema drift leaves health unknown and does not block dispatch.
