The distinction matters for routing. A current allowance percentage can block or permit a bounded attempt, but it does not tell us how much the next task will consume. A task's token count or displayed API-style cost cannot be subtracted from an invented subscription budget. Official [Codex app-server documentation](https://learn.chatgpt.com/docs/app-server) defines `account/rateLimits/read` as ChatGPT rate limits and `account/usage/read` as token-activity summaries; the installed thread-credit field is beyond that documented summary contract. Official [Codex pricing guidance](https://learn.chatgpt.com/docs/pricing) says model, context, reasoning, tools, retrieval, and caching affect usage, so a fixed prompt-length or public credit-price multiplier is insufficient. [OpenCode's CLI documentation](https://opencode.ai/docs/cli/) labels `stats` as session token/cost statistics. None of these read-only sources proves an actual per-model subscription draw.
