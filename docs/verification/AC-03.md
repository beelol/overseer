## Rationale per candidate

**Branch Diff — adopt.** Relevant surface is the review UI: versioned merge-base
comparisons, periodic reconciliation, editable stacked Monaco diffs with conflict-safe
edit/draft recovery (see [source assessment](../source-assessment.md)). MIT permits
copying and modification with the notice retained. It is the only candidate that is
already a VS Code extension, so it matches Overseer's UI host without porting.

**Agetor — skip code, keep as design reference.** Relevant surfaces: per-task git worktrees
under `~/.agetor/worktrees/`, per-account harness aliases implemented as a per-harness
`$HOME` override (`harnesses/<id>/`), tmux-hosted persistent Claude sessions, approval
detection from pane/JSONL transcript, SQLite run/event history. These overlap AC-05, AC-07
and AC-11, but the implementation is a Bun/Electrobun app process, not a separable library;
Overseer's daemon is Rust and its UI is VS Code, so the code would have to be rewritten
anyway. MIT would allow copying; if any snippet is later copied, add its notice here first.

**Parallel Code — skip.** Relevant surfaces: automatic per-task worktree creation (with
`node_modules` symlinking), diff viewer with inline review comments. No per-account
isolation surfaced in its README. Its review UI is Electron/SolidJS and duplicates what
Branch Diff already provides natively in VS Code.

**Pane — skip.** Relevant surfaces: session-managed worktrees, diff viewer tab, remote
control. AGPL-3.0 with additional attribution terms is incompatible with vendoring into an
MIT-noticed extension without relicensing Overseer under AGPL and adding Dcouple UI
attribution. Not adopted; no Pane code is to be copied or closely reimplemented.

**XCB — skip for now.** Relevant surface: account custody/routing (`xcb --json route`
selects a signed-in idle account and holds it until the provider process exits; see
`docs/route.md`). Conceptually close to AC-11/AC-12 and it is Rust + MIT, but its own
README states it is not yet a daily-driver replacement and it is a routing metaharness
rather than an interactive-session daemon. Revisit only if its tested route/custody
interfaces match Overseer's interactive-session requirements; record the new commit and
files here before copying.
