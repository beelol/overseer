# AC-144 — A lost session asks for attention
Status: verified
Tested implementation commit: 106d3e8 (pull request #5, merged into main as e0db692 on 2026-09-27)
Verification date and verifier: 2026-09-26, implementing agent (Claude Code)
OS / architecture / VS Code / harness versions: macOS 26.6.2 (25G83) arm64; VS Code 1.139.0 (stable, isolated --user-data-dir/--extensions-dir, VSIX installed with `code --install-extension`); Rust 1.89.0; Node 24.20.0; Git 2.50.1 (Apple); codex-cli 0.155.0-alpha.16.4 (ChatGPT.app bundle); Claude Code 2.1.246; OpenCode 1.15.13; overseerd 0.1.0 (protocol 1, parser 2026-09-24.1)
Harness, provider and redacted account identities (if applicable): Generic fixture programs; no accounts, no paid tokens
Prerequisites and fixture: Real Git repositories created per test; isolated OVERSEER_HOME; the daemon writes each cue it would play to a log

Steps or exact reproducible commands:

`CARGO_BUILD_JOBS=1 cargo test -p overseerd --offline --test audio -- --test-threads=1`, three protocol tests:
1. `a_lost_session_plays_one_attention_cue`: Audio Mode on; a top-level agent runs; its supervisor is killed.
2. `an_agent_stopped_on_request_stays_silent`: a running agent is interrupted.
3. `a_session_lost_while_the_daemon_was_down_makes_no_sound`: the daemon, the agent and its supervisor are killed; the daemon starts again.

Expected result: See the RFC criterion (Gate O) and the [Audio Mode RFC](../rfcs/audio-mode.md).

Actual result: - **Lost while the daemon runs:** the run becomes `disconnected`; the log holds the start cue and exactly one `agent_needs_attention`, also 500 ms after the agent itself is gone.
- **Stopped on request:** `interrupted`; the log holds the start cue only.
- **Lost while the daemon was down:** after the restart the run reads `disconnected` with "lost" as its reason, Audio Mode is still on, and 800 ms later the log still holds the start cue only.
- The daemon already behaved this way; nothing in it changed for this criterion.

Live vs fixture coverage: Fixtures with a real daemon.
