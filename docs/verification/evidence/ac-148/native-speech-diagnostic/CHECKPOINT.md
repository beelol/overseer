Its ordinary native test returned 85 samples and failed the existing >16,000 assertion. The cause remains unresolved.

This checkpoint adds only a `cfg(test)` module. The original `speak` implementation and ordinary tests, including the Err-only retry, are unchanged. The new ignored test is a **diagnostic one-attempt variant** in an isolated child process, with the same fixed synthetic phrase, default voice/rate, format, 20-ms initial wait, 10-ms global-busy polling and channel→extended-file→audio-file disposal order. Its additional observers/property reads and process isolation can change timing and concurrency; it is not the unchanged exact test or proof of the CI failure's cause.

The variant prints numeric metadata and fixed event labels only: bounded progress before native calls; per-channel done/error callback counts and error codes; checked current-voice creator/ID and description status; before/after status and error-property counts; callback byte counts, positions/timestamps; at most 16 WAV chunk declarations with available lengths; sample count and peak. No phrase, PCM bytes, error description/userInfo, arbitrary WAV tags or audio files are printed/written. A description failure leaves voice identity unqualified. Absence of an error callback does not establish service health.

All file clients and LP64 `SRefCon` values are opaque small IDs into a process-lifetime registry. Callbacks clone an owned slot; IDs are never dereferenced as addresses or reused. Four retained slots × 2 MiB audio, 64 event records per slot, and 16 parsed chunk receipts bound retained state. Simulated post-owner-drop callbacks and cap/ring assertions are authored in a non-native unit test. Disposal quiescence is not assumed; a final snapshot is not proof that no later callback occurred. Registry/trace/buffer mutexes are not held while invoking native channel operations, and file callbacks release the buffer mutex before taking the trace mutex.

The opt-in native parent owns a worker and enforces 35 seconds with kill+reap on timeout/unwind; a bounded 64-KiB pipe reader replays only diagnostic marker lines. Bounded progress records survive startup/disposal hangs. The worker itself preserves the original growing polling limit (22.9 seconds for this phrase); the parent additionally bounds startup and disposal. One native attempt is made; no retry loop. The worker's synthesis is memory-only. The existing length, sound and no-temporary-audio-file assertions are retained in the variant.

Existing parent's speech-status declarations are unchanged; diagnostic receipts narrow their low 16 bits to the SDK's `OSErr` width. Copied CF properties are released; borrowed dictionary members are not.
