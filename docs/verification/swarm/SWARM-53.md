# SWARM-53 — mutable resource isolation

Status: partial. Revisions: `fa376e9` (admission claims), `0d2074c` (durable planned claims), `83cc330` (late active conflict), `1d4ae16` (historical observations), `dc8a787` (completed-run verdict invalidation).

Input: two fixture categories request attempts against the same database namespace. Their admission requests declare `db:shared-test` as an exclusive write claim; the second also tries a read claim while the first writer remains active.

Expected: the conflict is detected before the second attempt or quota reservation is committed. Once the first worker's rejected attempt has confirmed exit and released the claim, the unchanged second request can proceed.

Actual: the pre-admission test initially admitted both writers. With resource claims acquired in the admission transaction, both conflicting requests return `resource_conflict`, the second job stays ready, and its attempt count remains zero. After the first attempt is reviewed and exits, the second writer is admitted. A later fixture moves exact write ownership into each durable job plan and omits it from both admission requests. Before `0d2074c`, both requests were admitted; now the second is blocked, and a request cannot downgrade the planned write to a read. The full offline Rust suite passed 152 tests (10 unit, 49 protocol, 93 Swarm) at `0d2074c`.

Earlier evidence: `docs/verification/swarm/milestone-13.md`.

Late observation fixture: Two admitted workers report use of `db:shared-late` after submitting finding artifacts. The second exclusive observation records contamination against both active attempts, moves both jobs to `cancel_requested`, queues their stop messages, keeps artifacts for audit, marks both coverage rows `contaminated`, and rejects acceptance. A replay of the observation is idempotent. After confirmed exits, both jobs become ready for another budget-checked admission; the retry uses a fresh `db:shared-late-reset` namespace. Repeating the collision on attempt 2 fails both jobs and prevents attempt 3. A separate test upgrades a declared read claim to observed write and quarantines both readers. Two observed readers of the same snapshot remain parallel. A supervised three-worker fixture confirms that a late collision requests interruption of the two affected processes while the unrelated process stays active. The daemon retries missed targeted stop signals after restart.

Historical observation fixture at `1d4ae16`: Worker A reports write use of `db:historical`, submits a checked-path artifact, receives an acceptance decision and exits. The daemon restarts. Worker B later reports write use of the same namespace. Expected: A's prior acceptance no longer counts as valid evidence and B cannot be accepted. Actual: the observation ledger survives restart; the conflict records contamination for both attempts, changes A's accepted job to blocked, marks its coverage `contaminated`, and cancels B. A separate fixture accepts A's result while its attempt remains registered, then reports A's late use after B; it also quarantines both. All 26 admission tests, 14 state/migration tests and the targeted supervised interruption test passed at `1d4ae16`. Reproduce with `cargo test --offline -p overseerd --test swarm_admission -- --test-threads=1`, `cargo test --offline -p overseerd --test swarm_state -- --test-threads=1`, and `cargo test --offline -p overseerd --test swarm_runtime late_resource_conflict_interrupts_only_affected_supervised_workers`.

Completed-run replay at `dc8a787`: A now completes with checked evidence before exiting. After restart, B reports conflicting write use of `db:historical`. Expected: the previous completion ceases to be a valid verdict while its original text and checks remain auditable. Actual: A's run changes from `completed` to `invalidated`, its saved completion reports `valid: false` with reason `resource_contamination` and the conflicting resource, and its accepted job and coverage are quarantined. A second restart retains that state. Stop and completion replay cannot restore the old verdict; a director batch claim returns `halted`. Fresh broker messages, artifact decisions and context grants on an invalidated run are guarded as terminal. Reproduce with `cargo test --offline -p overseerd --test swarm_admission --test swarm_integration --test swarm_state --test swarm_broker -- --test-threads=1`: 75 passed at `dc8a787`. An earlier parallel broker run had one transient OS socket error; the focused broker test and full broker suite then passed in isolation, and this record relies on the serial 75-test result.

Current evidence: `daemon/tests/swarm_admission.rs`, `daemon/tests/swarm_runtime.rs`.

Remaining: The late observation API is fixture-only and relies on an explicit resource name supplied by the caller. Live tool/resource discovery, canonical aliases, external service mutation detection, and a full Atlas replay are not implemented. When a conflicting planned owner has no active registered attempt and no recorded use, overlap cannot be proved and the observation is rejected without quarantine. This case needs a conservative production rule before enabling live observation.
