# SWARM-30 — director replacement

Status: partial. Latest code revision: `f802c1c`; earlier supervised-process revision `acc097a` and recovery revisions `0fc1446`, `3d7bc31` and `e89bc7d`.

Input: a fixture-admitted worker with a reserved quota window reports a discovery. The director claims it, and the daemon restarts before the batch is applied. The worker sends a late terminal result while director termination is uncertain. The fixture then reports confirmed director death.

Expected: uncertainty holds new coordination and keeps usage reserved; confirmation advances the director generation, requeues unapplied messages, keeps worker results, and rejects old director commands.

Actual: the run enters `stalled` on unknown termination. Claiming another director batch and sending an old directive fail; the worker result remains durable and its reservation stays active. Confirmed death increments generation from 1 to 2. The replacement claims both the original discovery and the late result, while the original completion token/directive is rejected. The focused test first failed because recovery did not exist, then passed after the transition was added. The workspace suite passed with 68 tests at revision `0fc1446`.

Follow-up: Pause and Resume cannot bypass an uncertain director stall. A separate crash-and-restart fixture starts paused, receives repeated unknown-termination reports, then confirms death; replacement restores `paused` rather than silently resuming admission. The previous implementation returned `planning` in the red test. An additive schema migration persists the pre-stall state; the workspace suite passed 76 tests after the fix.

Evidence: `daemon/tests/swarm_director.rs`, `daemon/tests/swarm_director_owner.rs`, `daemon/tests/swarm_director_process.rs`, `daemon/tests/swarm_state.rs`, `docs/verification/swarm/milestone-11.md`.

Remaining at `0fc1446`: the fixture supplied termination evidence; no supervised process identity/liveness proof, replacement target selection, model turn, or unavailable-replacement recovery was implemented. This was not proof that a real director could be safely killed or resumed.

The versioned Atlas [S5](S5.md) replay now combines confirmed director death with a committed dispatch intent before worker acknowledgement. Generation 2 retains and launches one J2 worker after daemon restart; generation-1 claims, revision and directive fail, and the replacement accepts its database-backed finding. This adds a joined backend trace but does not establish live director death detection or replacement model behavior.

Owner-credential follow-up: `daemon/tests/swarm_director_owner.rs` binds a random director token whose hash and 30-second lease persist in SQLite. The fixture first failed because no owner binding existed. Once bound, tokenless or wrong-token plan, inbox-claim, directive, review and turn-completion calls fail; the owner can renew and continue after daemon restart. An expired lease rejects mutation and excludes the run from central admission. The daemon deadline tick records `director_termination_unknown` without releasing the owner. A second owner cannot bind from timeout alone, and owner binding cannot take over an active unowned director turn. Confirmed-dead fixture recovery releases generation 1, requeues unapplied work, advances to generation 2 and leaves `director_replacement_pending`; no new admission resumes until generation 2 binds a new token. A previously committed launch intent may still reconcile by its durable ID. The former token cannot revise the new generation. The test also checks that `swarm.get` does not expose the owner token. The owner checks cover direct admission, benefit commits, resource claims, context grants/revocations, integration and verification preparation in addition to the exercised plan/review path. `cargo test --offline -p overseerd --test swarm_director_owner` passes all three cases. The full offline workspace suite passed 217 non-ignored tests, with 11 ignored.

Supervised-script follow-up at `acc097a`: `daemon/tests/swarm_director_process.rs` launches a fixture-only generic director under Overseer's normal process supervisor. The daemon binds its owner before launch and passes its credential through the private mode-0600 launch file and child environment, returning only the supervised run ID. Input: one director sleeps while the daemon restarts, then is interrupted; a replacement is launched for generation 2. Expected and actual: `confirmed_dead` is rejected both before and after daemon restart while the first process is running; only the recorded supervisor exit permits replacement. The replacement links its own process rather than inheriting generation 1's link, and cannot be replaced while active. An ordinary task follow-up cannot bypass director coordination. A second fixture uses a nonexistent executable: the supervisor records the failed child spawn and its exit before recovery succeeds. The migration test preserves an existing owner reservation while adding the nullable process link. These tests were red first for the missing launch route, inherited process link, missing migration and ordinary follow-up bypass. The full `cargo test --offline --workspace` run passed 220 non-ignored tests with 11 ignored after the changes.

Remaining after this follow-up: the director process path is a scripted local fixture, not a qualified Codex/Claude/OpenCode model director. It does not yet consume durable broker batches or autonomously propose plan/review actions. Launch binding and process linking are separate durable steps; an interruption between them needs reconciliation rather than assumed replacement. The Auto Mode allowance transaction, live replacement target availability and unavailable-provider fallback remain unqualified. The 30-second lease is a fail-closed coordination limit, not proof that an unreachable process stopped consuming allowance.

Crash-boundary follow-up at `f802c1c`: `daemon/tests/swarm_director_process.rs` injects two deterministic SQLite failures into the real fixture launch route. First, a failure while recording generic launch metadata occurs after the task/run transaction but before the supervisor starts. The red test found an unlinked queued run. The fix links the director owner and run in that same transaction; the green test finds the durable link, no run directory, and no permission to replace the director based on caller assertion alone. Second, a failure before task insertion leaves an owner with no process link. The red test showed that `confirmed_dead` incorrectly advanced its generation. A migrated `supervised_launch` marker now makes this owner fail closed, while legacy unlinked scripted-owner fixtures retain their separate termination-evidence path. The schema migration test verifies old owner rows gain the marker with default zero and retain their reservation. `cargo test --offline -p overseerd --test swarm_director_process` passed all four cases, and `cargo test --offline --workspace` passed after this change; `git diff --check` passed. The repository-wide `cargo fmt --all --check` remains unsuitable as a change gate because extensive pre-existing files are unformatted; this patch did not reformat unrelated code.

Remaining after `f802c1c`: a supervised owner whose launch fails before task/run insertion is safely held but has no automatic no-process reconciliation, so a subsequent launch needs a qualified recovery path. A linked run whose launch stops before supervisor creation also needs a durable no-spawn proof before safe release. Normal live model-director turns, broker-driven coordination, Auto Mode shared allowance admission, and provider-path exit proof remain unverified. SWARM-30 stays partial.
